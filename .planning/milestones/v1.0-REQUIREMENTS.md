# Requirements: Trabajo CBD -- App iOS con SQLite

**Defined:** 2026-04-06
**Core Value:** Un documento academico completo y entregable que demuestre empiricamente el rendimiento de SQLite en iOS, acompanado de un prototipo React Native funcional que sirva de evidencia de la implementacion.

## v1 Requirements

### DOC -- Documento academico

- [x] **DOC-01**: El documento incluye una Introduccion con la estructura requerida: atencion -> contexto -> proposito -> metodologia -> resultados breves -> conclusiones breves, con una idea por parrafo
- [x] **DOC-02**: El documento incluye un Estado del Arte con comparativa argumentada de AsyncStorage, Realm y expo-sqlite, justificando la eleccion de expo-sqlite para datos financieros tabulares
- [x] **DOC-03**: El documento incluye la seccion Alcance y Funcionalidades con Tabla 1 que mapea cada funcionalidad de la app al concepto de BD que demuestra
- [x] **DOC-04**: El documento incluye la seccion Metodologia/Diseno con esquema E/R y esquema fisico SQL (CREATE TABLE completo con constraints)
- [x] **DOC-05**: El documento incluye la seccion Implementacion con fragmentos de codigo TypeScript comentados en espanol y explicacion academica de cada componente de BD (PRAGMA, triggers, consultas de agregacion)
- [x] **DOC-06**: El documento incluye la seccion Resultados y Pruebas con metricas medidas en simulador iOS: tiempo de consulta con/sin indice, tiempo de insercion de N transacciones en bloque
- [x] **DOC-07**: El documento incluye Conclusiones que resumen resultados, implicaciones teoricas/practicas, limitaciones (sin backup remoto) y trabajos futuros (sincronizacion cifrada), sin repeticion literal del cuerpo
- [x] **DOC-08**: El documento incluye lista de Referencias en formato IEEE numeradas por orden de aparicion en el texto
- [x] **DOC-09**: El documento incluye una seccion de Declaracion de Uso de IA con enlace a cada conversacion de IA utilizada para generar contenido

### FMT -- Formato y calidad academica

- [x] **FMT-01**: Cada tabla tiene: numero (Tabla 1, Tabla 2...), titulo en cursiva encima y nota al pie con *Nota.* indicando fuente si es externa; el texto la referencia antes de mostrarla ("En la Tabla X se muestra...")
- [x] **FMT-02**: Cada figura tiene: numero (Figura 1, Figura 2...), titulo en cursiva debajo y nota al pie con fuente si es externa; el texto la referencia antes ("En la Figura X se puede observar...")
- [x] **FMT-03**: Cada afirmacion tecnica esta respaldada por al menos una cita IEEE [N] real y verificable
- [x] **FMT-04**: El texto no contiene plagio mosaico ni copia-pega: todas las ideas tomadas de fuentes externas estan parafraseadas y citadas

### BD -- Base de datos (esquema, DDL y logica SQL)

- [ ] **BD-01**: Proyecto Expo SDK 54 inicializado con `expo-sqlite@~14.0.6` y TypeScript; verificado que la app arranca en Expo Go (SDK 54 incluye expo-sqlite como librería nativa empaquetada)
- [ ] **BD-02**: Modulo `src/db/database.ts` con funcion `migrateDbIfNeeded` que ejecuta: `PRAGMA foreign_keys = ON`, `PRAGMA user_version`, y todos los `CREATE TABLE IF NOT EXISTS` en una sola llamada a `openDatabaseAsync`
- [ ] **BD-03**: Esquema completo con 4 tablas: `cuentas` (id, nombre, tipo), `categorias` (id, nombre, tipo), `transacciones` (id, cuenta_id FK, categoria_id FK, tipo, importe CHECK >0, fecha, descripcion), `presupuestos` (id, categoria_id FK UNIQUE, mes, limite, restante)
- [ ] **BD-04**: Integridad referencial: FK `transacciones.categoria_id` con `ON DELETE CASCADE`; FK `transacciones.cuenta_id` con `ON DELETE RESTRICT`; demostrar diferencia en la app
- [ ] **BD-05**: Trigger `actualizar_presupuesto_tras_gasto` (AFTER INSERT ON transacciones WHERE tipo='gasto') que actualiza `presupuestos.restante`; trigger simetrico AFTER DELETE para revertir
- [ ] **BD-06**: Indices: `CREATE INDEX idx_txn_fecha ON transacciones(fecha)` y `CREATE INDEX idx_txn_categoria ON transacciones(categoria_id)`
- [ ] **BD-07**: Vista SQL: `CREATE VIEW resumen_mensual AS SELECT categorias.nombre, strftime('%Y-%m', fecha) AS mes, SUM(importe) AS total FROM transacciones JOIN categorias ... GROUP BY categoria_id, mes`

### APP -- Funcionalidades de la aplicacion

- [ ] **APP-01**: Pantalla de cuentas: lista de cuentas con balance calculado en SQL (`SUM CASE WHEN tipo='ingreso'`), formulario para anadir cuenta nueva
- [ ] **APP-02**: Pantalla de categorias: lista con opcion de eliminar; al eliminar una categoria con transacciones asociadas se activa CASCADE y se eliminan las transacciones; al intentar eliminar una cuenta con transacciones se bloquea con RESTRICT
- [ ] **APP-03**: Pantalla de nueva transaccion: formulario (importe, tipo ingreso/gasto, cuenta, categoria, fecha); la insercion se ejecuta con `withExclusiveTransactionAsync` para garantizar ACID
- [ ] **APP-04**: Pantalla de presupuestos: lista de presupuestos con `limite` y `restante` por categoria/mes; formulario para crear nuevo presupuesto
- [ ] **APP-05**: Pantalla de informe mensual: consulta `SELECT categorias.nombre, SUM(importe) FROM transacciones JOIN categorias GROUP BY categoria_id WHERE strftime('%Y-%m', fecha) = ?` ejecutada en el motor SQLite; resultado mostrado en FlatList
- [ ] **APP-06**: Boton "Generar datos de prueba" que inserta 100-500 transacciones aleatorias con `withExclusiveTransactionAsync`; mide y muestra el tiempo total de insercion para la seccion de Resultados
- [x] **APP-07**: Capturas de pantalla del prototipo funcionando en simulador iOS (minimo: lista de transacciones, informe mensual, pantalla de presupuesto con restante actualizado por trigger)

### DEF -- Defensa

- [x] **DEF-01**: Presentacion de diapositivas con figuras y mensajes clave extraidos del documento (no transcripcion del texto); incluye diagrama E/R, tabla comparativa de SGBD, fragmento de codigo del trigger y captura de la app

## Out of Scope

| Feature | Razon |
|---------|-------|
| Autenticacion de usuarios | 3-5h de implementacion, ningun concepto de BD demostrado; la app corre en un unico dispositivo local |
| Sincronizacion con servidor (online/hibrida) | Intencionalmente offline-first para aislar metricas del SGBD de la latencia de red |
| SQLCipher / cifrado AES-256 implementado | Requiere build nativo personalizado (+4-6h); se menciona teoricamente en el Estado del Arte |
| Version Android | El trabajo pide explicitamente iOS |
| Graficas / charts avanzados | El deliverable academico es la consulta SQL, no la visualizacion; FlatList es suficiente |
| ORM (Drizzle u otro) | Oculta el SQL que la profesora evalua; usar raw expo-sqlite API |
| Export CSV/PDF | Feature de app, no de BD; 2-3h por cero puntos academicos |
| Transacciones recurrentes | Requiere scheduling de app, no concepto de BD |
| Multi-divisa | Complejidad anadida sin nuevo concepto de BD; hardcodear EUR |
| Tests automatizados | Fuera del alcance de 30h |
